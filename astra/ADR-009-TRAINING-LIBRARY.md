# ADR-009: Private workout bookmarks and exercise history

Accepted implementation scope, 6 September 2026. Extends ADR-007 and ADR-008 on `review/mobbin-fidelity`; no stack replacement.

The client can browse workouts already assigned to their selected coaching relationship, search titles/exercise names, filter prescribed timed work plus rest, and save private favorites. This does not publish private coach programs or create a public on-demand catalog. Timed targets are not estimates of whole workout duration. Existing `session.start` remains responsible for distinct genuine attempts, resumption, and training entitlement checks.

`workout_favorites` keys an account and an existing scheduled instance. RLS exposes only the active account's bookmarks. Direct writes and anonymous access are denied. `training.favorite` takes `scheduledId`, a boolean desired state, and a revision; it checks client ownership, serializes actor edits, preserves command idempotency, and logs the acknowledged change. Unfavoriting retains a false row and revision so a stale tab cannot silently overwrite a newer choice. At most 2,000 rows are accepted per account. No ownership fields come from the browser. Export includes the actor's favorites.

`GET relationships/[id]/favorites` and `GET workout-sessions/[id]/exercise-history/[exerciseId]` use authenticated server-side RPC calls. Exercise history inherits existing relationship/session/set RLS, requires the exact exercise identity from the requested prescription, and returns completed attempts with real set values. It never groups unrelated exercises by a similar name. The result contains a server `as_of` instant for stable range filtering and an explicit `has_more` flag beyond the 100 most recent matching attempts. Assigned coaches retain existing authorized history access; another coach and a sibling client are denied. Coaches cannot read the client's private favorites.

Completed or abandoned sessions now remain on their saved summary rather than immediately navigating away. Summary/exercise tabs display actual elapsed time and recorded sets; no calorie estimate, performed repetitions, feedback, or shared public link is fabricated. The summary's weekly check-in link opens the existing flow and sends nothing by itself. Exercise history is loaded only when its player sheet is opened.

## Addendum: private session feedback and explicit coach submission

Accepted bounded extension, 6 September 2026, starting HEAD `e79a7355f5305606af9fbd1c303fb6f517e8d6be`. The earlier feedback/flag exclusions above describe the training checkpoint; this addendum supersedes only those exclusions. The pinned visual world, Gymaf identity and existing session/prescription authority remain unchanged.

`session_feedback` stores one private draft per workout attempt with a revision and a separately submitted snapshot/revision/time. The member can edit a nullable 1–5 rating/difficulty, a comment up to 2,000 characters, and up to 30 unique prescribed-exercise flags, each with one or more allowed reasons and an optional comment up to 1,000 characters. `feedback.save` validates ownership, shape, prescription membership and expected revision, serializes actor edits, records audit/idempotency evidence and returns the new revision. Explicit application conflicts use `GY409`, mapped to HTTP 409. Draft saves neither change prescriptions nor notify the coach.

`feedback.submit` accepts only the saved session/revision. It requires a nonempty draft, a completed or abandoned attempt, and an active relationship/workspace. It locks the relationship and attempt during submission, copies the draft into the shared snapshot, and adds a notification for the assigned coach only when that revision has not already been shared. Retrying a command or resubmitting the same revision does not duplicate the notification. Editing afterward changes only the private draft; a later explicit submission replaces the shared snapshot. This stores the latest submitted snapshot, not an immutable history of every past submission.

The authenticated feedback query returns the owner's draft/revision; an authorized coach receives only the submitted snapshot/revision. Table RLS allows owner reads, denies direct authenticated writes, and exposes no draft table reads to coaches. Anonymous query/command execution is revoked. Export queries filter to the actor's own attempts, and the account export includes `sessionFeedback`. API routing and shared validation enforce the same command shape; neither owner nor recipient is browser-supplied.

The summary exposes Feedback alongside Summary/Exercises. Player and summary flag editors support reason/comment/edit/remove with acknowledged private saves. Save Draft and explicit Send have different effects. Dirty exit offers Save Draft and Leave, Keep Editing, or Discard and Leave; failed-flag reload makes replacement explicit. `feedback-drafts.ts` keeps account/session-keyed unsaved edits in document memory through same-document history, preserving the original revision for safe stale-write conflicts. Auth changes/sign-out clear that cache; it is not disk persistence, offline support or server acknowledgement. Discarding the last unchanged flag draft also removes its unused parent baseline.
